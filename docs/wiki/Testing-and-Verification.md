# 検証

ZORKERB r29 について行った検証の環境、方法、範囲、結果をまとめます。

検証に使ったツール、試験データ、比較用の解釈系と原作 story、生の報告は、開発用の非公開リポジトリに保存しています。この文書は、その記録から確認済みの結果をまとめたものです。

## 実行環境

| 項目 | 内容 |
| --- | --- |
| エンジン | PyEmuera 3.0.0b2（未改変、SHA-256 `8473b250080ba678e05b4f484fcc6790f96614c2e9a7aaab077ab379e05f4bcb`）。この配布物に同梱しているものと同じファイルです。 |

## 方法

### 凍結した1回の実行

検証は一度にまとめて実行します。

1. 開始時に、ソース・試験・ツール、生成したゲーム、エンジンの SHA-256 を記録します。
2. すべての検査を行います。
3. 終了時に、記録した値から何も変わっていないことを確かめます。

ソースを変えた場合は、最初からやり直します。

### 回帰試験

1,596件の試験を未改変の PyEmuera で実行し、次を検査します。

- 指定した文が出力に含まれるか、含まれないか
- 手数、得点、物体の位置、フラグなどの状態
- セーブの内容と、保存・復帰後の状態

期待値は、原作の応答と原典の処理に基づいています。r29 で期待値を直した38件は、すべて原作で同じ入力を再生して確かめています。

### 原作との比較

同じ入力を原作と ZORKERB に与え、1手ごとの応答と、最後にセーブした状態を比べます。

- **乱数列を揃えた比較：** 各ケースの先頭に原作のデバッグ命令 `#random 997` を加えます。両者が同じ乱数列を引くので、文章と状態を厳密に比べられます。完成の判定にはこの比較を使います。
- **固定 seed の比較：** seed を固定しただけでは、PyEmuera と Frotz の乱数列は一致しません。参考として記録しています。
- **文章の正規化：** ASCII の空白（改行位置を含む）と、Frotz のハイフンでの折り返しだけです。語句は正規化しません。
- **状態の比較：** セーブから取り出した次の値で行います。
  - 現在地、得点、手数
  - 持ち物の順序
  - 指定した物体の親子関係とフラグ
  - IT

  メモリ全体の一致を確かめたものではありません。

### プローブと全経路

- **プローブ：** 特定の場面を原作と1手ずつ比べる入力です。Loud Room、ボート、ロープ、機械、全構文行、地域ごとの長い操作列などがあります。
- **全経路：** 宝物を集める長い経路を、乱数列を揃えて原作と1手ずつ比べます。

### 通常の入力だけの完走

559個の入力で、新しいゲームから終幕までを遊びます。SAVE・RESTORE や検証用の命令は使いません。

### 原作との比較の内訳

| 比較集合 | 件数 | 文章が厳密に一致 | 状態が一致 |
| --- | ---: | ---: | ---: |
| pseudo | 56 | 56 | 56 |
| holdout | 62 | 62 | 62 |
| edges | 24 | 24 | 24 |
| older（以前の版の18集合） | 659 | 657 | 657 |

older の残り2件は、IT が物体0を指したまま `examine it` とする経路です。原作はこの操作で `get_parent` と `test_attr` を物体0に対して実行し、厳格な解釈系はそこで停止します。

- 寛容な解釈系（Frotz の `-Z 1`）で再実行すると、解釈系の警告行を除いて、文章・応答数・状態が ZORKERB と一致します。
- 停止するまでの手（31手と8手）は厳密に一致します。
- この2件は、厳密な一致の件数には含めていません。

固定 seed の比較では、文章が厳密に一致したのは 69件/142件、状態の一致は 142件/142件でした。同じ142件を乱数列を揃えて比べると、文章も状態もすべて一致します。そのため、固定 seed での文章の違いは乱数列の違いによるものと判断しています。

## 配布物の検査

配布物については、次を確かめています。

- ZIP の SHA-256、CRC、ZIP 内の SHA256SUMS
- 重複、危険なパス、不要なファイルがないこと
- 収録した `ERB/`・`CSV/` が、検証したゲームとバイト単位で一致すること
- 文書の相対リンクが配布物の中で解決すること
- 展開した配布物だけで、次の操作列が動くこと：新規ゲーム → リーフレットを取る → `save 0` → 置く → `restore 0` → 持っている状態に戻る → RESTART → SCORE → QUIT
- 展開した配布物だけで、350点経路が終幕まで進むこと
